# Як AI допомагає готувати чеклісти для здачі навчальних завдань

## План роботи

| Поле | Рішення |
| --- | --- |
| Проблема | Перед початком нової лабораторної або контрольної роботи студенту потрібно виписати кроки, обов’язкові файли, правила здачі й дедлайни. У довгих умовах ці відомості розміщені в різних розділах. |
| Поточний процес | Прочитати умову, виписати обов’язкові пункти, звірити список з оригіналом і зберегти його. У трьох умовах для перевірки визначено 30 контрольних вимог. |
| Дані | Текст умов у UTF-8. Для перевірки використано умову цієї МКР і два короткі перекази опублікованих матеріалів курсів. [Опис джерел](evidence/README.md) |
| Рівень рішення | **1 — Prompt.** ChatGPT за один запит групує вимоги та наводить цитати. Вся потрібна інформація надходить у самому запиті. |
| Метрика успіху й ціль | Скоротити середній час до перевіреного чекліста щонайменше на **40%**. Після звірки чекліст має містити **100%** контрольних вимог і не містити хибних вимог або дедлайнів. |
| Ризики й запасний варіант | Звіряти чекліст з умовою та доповнювати пропущене. Якщо модель недоступна або текст неповний, сформувати чекліст вручну за оригіналом. |

## Архітектура й вибір підходу

1. **Вхід.** Браузерний інтерфейс приймає вставлений текст або файл TXT/MD. JavaScript додає текст до шаблону промпту.
2. **AI.** ChatGPT аналізує умову одним запитом і повертає JSON. Для кожного кроку, артефакту, дедлайну, обмеження або опції модель додає фрагмент оригіналу. Якщо дедлайну немає в наданому тексті, модель повертає порожній список дедлайнів.
3. **Звірка й вихід.** Спільний JavaScript-модуль перевіряє структуру та шукає наведені фрагменти в умові. Користувач звіряє також зміст і повноту, після чого зберігає Markdown. Той самий модуль працює з термінала через Node.js.

| Підхід | Що визначило вибір |
| --- | --- |
| Один промпт до ChatGPT | Модель розпізнає вимоги навіть у розгорнутому тексті. Точні назви, команди й числа можна зіставити з цитатами. Підхід відповідає рівню 1. |
| Пошук за ключовими словами | Міг би знайти типові назви файлів і дати. Обов’язковість пункту, умовні правила й альтернативи часто залежать від контексту. |
| RAG | Міг би знадобитися для завдань, де правила й дедлайни розміщені в різних документах. У перевірених випадках вміст потрібного фрагмента вже доступний на вході. |

Використано ChatGPT для генерації, HTML/CSS та JavaScript для інтерфейсу, Node.js для команд термінала. Точна версія моделі в діалозі не фіксувалася. API-інтеграція не потрібна. Команди запуску є в [solution/README.md](solution/README.md).

## Ризики й обмеження

| Ризик | Ймовірність / наслідок | Що робити |
| --- | --- | --- |
| Модель пропускає вимогу, хоча всі її цитати є в джерелі | Середня / висока для правил здачі | Прочитати оригінал і перевірити кожну групу. Дописати пропущений пункт із цитатою та повторити експорт. |
| Помилковий дедлайн, неправильна назва файлу або цитата, що стосується іншого пункту | Середня / висока | Відкрити цитату під пунктом і звірити її зміст, дату, час, часовий пояс і назву. Запитати викладача, якщо в умові є суперечність або неоднозначність. |
| AI повертає JSON з помилкою | Середня / середня | Скопіювати весь об’єкт, повторити запит за потреби. Прототип показує помилку та блокує експорт, якщо бракує полів або цитату не знайдено. |
| ChatGPT недоступний або вичерпано ліміт | Низька для окремого прогону / середня | Скласти чекліст вручну. Раніше отриманий JSON можна експортувати локально. |
| Умова у вигляді скану, неповна або посилається на додаток | Середня / висока | Перенести текст із PDF або фото й додати вимоги з додатка. Звірити результат зі справжнім джерелом. |
| Навчальний документ містить персональні дані | Залежить від джерела / високий | Перед копіюванням у зовнішній сервіс видалити дані, які не потрібні для чекліста. |

## Перевірка й результат

Практичний випадок — підготувати чекліст для здачі цієї МКР. Два додаткові прогони перевіряють точну команду здачі без дати та історичний дедлайн із трьома іменами файлів. Для кожного прикладу збережено вхід, JSON від ChatGPT і фактичний експорт програми.

| Умова | Знайдені цитати | Обов’язкові пункти в першій відповіді | Після звірки |
| --- | ---: | ---: | ---: |
| МКР 1 | 31 / 31 | 16 / 18 | 18 / 18 |
| CS50P Indoor Voice | 7 / 7 | 5 / 5 | 5 / 5 |
| MIT OCW Problem Set 1, вступ | 8 / 8 | 7 / 7 | 7 / 7 |
| **Разом** | **46 / 46** | **28 / 30** | **30 / 30** |

У першій відповіді для МКР були шлях `mkr1/solution/` і рядок вартості. Після звірки додано вимоги розташувати код саме в репозиторії та зіставити вартість прогону із цінністю заощадженого часу. Контрольний прогін із навмисно заміненою цитатою повернув помилку й не створив файл. Для хронометражу на кожному прикладі відлік починається з відкриття умови й завершується після звірки готового чекліста. Прогін із AI включає копіювання запиту, очікування відповіді, виправлення та експорт. Економія у відсотках обчислюється як `(середній час до − середній час після) / середній час до × 100%`. Щоб зменшити ефект запам’ятовування, між проходами можна зробити перерву та чергувати порядок варіантів на різних умовах. [Таблиця замірів](evidence/measurements.csv)

## Відповіді на 12 питань

1. **Яку проблему вирішено?** Виділення вимог із довгих умов та підготовка одного списку для планування й здачі.
2. **Чому проблема реальна?** У цій МКР потрібно зіставити окремі розділи завдання, результату й формату здачі. Таке читання повторюється з кожною новою роботою, де вимоги розкидані по тексту.
3. **Як задача виконувалася до AI?** Прочитати умову, вручну сформулювати пункти та перевірити список за оригіналом.
4. **Яке рішення побудовано?** Локальний браузерний інтерфейс і CLI, які готують промпт, приймають JSON від ChatGPT, перевіряють цитати й експортують Markdown.
5. **Чому рівень 1?** Для наданих на вхід умов вистачає одного запиту. Форматування і звірку цитат виконує звичайний код.
6. **Які альтернативи розглянуто?** Пошук за ключовими словами та RAG для кількох джерел. Переваги підходів наведено в таблиці архітектури.
7. **Які моделі й інструменти використано?** ChatGPT, JavaScript, HTML/CSS, Node.js і локальний HTTP-сервер Python для браузерного інтерфейсу.
8. **Які помилки виникли?** У першій відповіді для МКР пропущено дві деталі. Дослівність усіх цитат пройшла перевірку, тому пропуски знайдено під час звірки змісту.
9. **Наскільки рішення надійне?** Перша відповідь покрила 28 із 30 вимог у трьох прогонах. Переглянуті чеклісти покрили всі 30. Для інших умов потрібна така сама звірка, особливо для дедлайнів і форматів здачі.
10. **Що змінилося?** Чернетка вимог одразу згрупована за призначенням. Під час ручного перегляду можна перевірити готові формулювання й дописати пропущене.
11. **Скільки ресурсів вдалося заощадити?** Модель підготувала пункти для 28 із 30 контрольних вимог. Економію часу можна оцінити після особистого хронометражу.
12. **Що можна покращити далі?** Додати імпорт текстових PDF і пошук фрагмента умови за натисканням на цитату. На більшій вибірці перевірити, чи це впливає на час та кількість пропусків.
